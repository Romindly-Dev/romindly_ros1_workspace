# 01 实机部署清单

> English version: [01_deployment_checklist.md](../en/50_deployment/01_deployment_checklist.md)

## 目标

从一台空白的 x86_64 边缘单元开始，按 checklist 走完系统设置 → ROS 安装 → 时间同步 → 工作空间部署 → 网络配置 → 验收测试，最终得到一台"环境可复现、随时可交给 02 节配自启"的机器。

## 背景

部署和开发的最大区别是**不可复现的手工操作是负债**：三个月后第二台机器要复刻今天的环境时，任何"当时随手改的"都会变成坑。所以本节所有步骤都以命令形式给出，建议整理成你们自己的部署脚本。另一个背景是 ROS Noetic 已于 2025-05 EOL：apt 源仍在但不再更新，裸机安装依然可行，长期维护更推荐 [03 Docker 部署](03_Docker部署.md)。

## 第一步：Ubuntu 20.04 基础设置

安装 Ubuntu 20.04.x（Desktop 或 Server 均可；无人值守机器推荐 Server/最小安装，省内存也少后台干扰）。装完先做三件事：

```bash
# 1. 关闭自动休眠/挂起（现场机器休眠 = 机器人失联）
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target

# 2. 关闭自动更新（避免半夜 unattended-upgrades 拉包、占 apt 锁甚至重启）
sudo systemctl disable --now unattended-upgrades apt-daily.timer apt-daily-upgrade.timer

# 3. 有桌面的机器再关闭图形层的空闲挂起
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-ac-type 'nothing' 2>/dev/null || true
```

验证：`systemctl status sleep.target` 应显示 `Loaded: masked`。

## 第二步：安装 ROS Noetic（含 apt key 过期修复）

完整安装流程见 [00 章](../00_环境搭建/01_Ubuntu20.04_ROS_Noetic安装.md)，边缘单元通常装 `ros-noetic-ros-base`（不含 rviz/rqt 等 GUI）即可，再按 `ros1.repos` 用 rosdep 补依赖。

### 必读：EXPKEYSIG 报错修复

ROS 官方 apt 源的 GPG 签名 key 在 2025 年中轮换过。老镜像装出来的系统、或按旧教程配的源，`apt update` 会报：

```
Err:5 http://packages.ros.org/ros/ubuntu focal InRelease
  The following signatures were invalid: EXPKEYSIG F42ED6FBAB17C654 Open Robotics <info@osrfoundation.org>
```

修复方法是重新下载最新的 ros.key 覆盖旧 keyring：

```bash
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg
sudo apt update
```

同时确认源条目引用了该 keyring（新式写法）：

```bash
echo "deb [signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros/ubuntu focal main" \
  | sudo tee /etc/apt/sources.list.d/ros-latest.list
```

> 用清华镜像源的机器同样可能碰到（镜像同步官方签名），修复方法相同。这一步建议写进部署脚本，新老机器统一执行一遍。

## 第三步：时间同步（chrony）

多机部署时，TF、传感器消息都靠时间戳对齐：两台机器差几百毫秒，TF 就会报 `extrapolation into the past`，融合与建图全乱。传感器（如 Velodyne）打的时间戳也依赖主机时钟。用 chrony 替代默认的 systemd-timesyncd，收敛更快、支持内网互为时源：

```bash
sudo apt install -y chrony
```

有外网的机器用默认配置即可；**无外网产线**让主控机当时间服务器，编辑 `/etc/chrony/chrony.conf`：

```bash
# —— 主控机（时间服务器）追加 ——
allow 192.168.1.0/24
local stratum 8          # 无外网也对外提供本机时间

# —— 其余机器：注释掉 pool 行，指向主控机 ——
server 192.168.1.10 iburst
```

```bash
sudo systemctl restart chrony
chronyc tracking          # 看 System time 偏差
chronyc sources -v        # 从机上应看到主控机为 ^* 选中源
```

验收标准：`chronyc tracking` 中 `System time` 偏差 < 10ms。

## 第四步：部署工作空间（两条路线）

| 路线 | 做法 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| A. 源码部署 | 机上 `vcs import` 拉源码 + `catkin_make` | 与开发机流程一致，机上可改可调 | 依赖外网/编译工具链，编译慢，机上代码易被现场改乱 | 试点样机、需现场调试 |
| B. 拷贝编译产物 | 开发机编好，把 `install/` 整目录拷到机上 | 无需外网与编译器，部署快、产物只读 | 开发机与目标机的系统/依赖必须一致；漏拷 apt 依赖会缺库 | 批量产线部署 |

**路线 A**（与 [00 章工作空间篇](../00_环境搭建/02_工作空间与代码拉取.md)相同）：

```bash
mkdir -p ~/ws_romindly/src && cd ~/ws_romindly
git clone https://github.com/Romindly-Dev/romindly_ros1_workspace.git src/romindly_ros1_workspace
vcs import src < src/romindly_ros1_workspace/ros1.repos
rosdep install --from-paths src --ignore-src -r -y
catkin_make && catkin_make install
```

**路线 B**：开发机 `catkin_make install` 后：

```bash
rsync -avz ~/ws_romindly/install/ iot@192.168.1.10:~/ws_romindly/install/
# 目标机上 source install 空间即可运行
source ~/ws_romindly/install/setup.bash
```

### 为什么产线要用 install space

`devel/` 里大量文件是**软链回 src/ 源码**的，拷走会变成断链；`catkin_make install` 生成的 `install/` 是自包含的成品目录（binaries + launch + config + setup.bash），不依赖 src 存在。产线部署只发 install 空间，意味着：现场没有源码可乱改、目录能整体校验（md5）、回滚 = 换目录。注意 `robot_bringup` 这类包的 launch/config 要在 CMakeLists 里正确 `install()` 才会进 install 空间。

## 第五步：网络配置

### netplan 静态 IP

边缘单元必须固定 IP（写法与 [45 章](../45_传感器驱动/04_udev规则与设备管理.md)雷达网口一致）。编辑 `/etc/netplan/01-robot.yaml`：

```yaml
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: no
      addresses: [192.168.1.10/24]
      routes: [{to: default, via: 192.168.1.1}]
      nameservers: {addresses: [223.5.5.5, 8.8.8.8]}
```

```bash
sudo netplan apply && ip addr show enp1s0
```

### 多机 ROS 配置

设主控机（跑 roscore）192.168.1.10，操作台 192.168.1.20，两台机上分别设置：

```bash
# 主控机
export ROS_MASTER_URI=http://192.168.1.10:11311
export ROS_IP=192.168.1.10
# 操作台
export ROS_MASTER_URI=http://192.168.1.10:11311
export ROS_IP=192.168.1.20
```

**最大的坑：hostname 解析。** ROS1 节点注册时上报自己的地址，默认用 hostname；对方解析不了这个 hostname 时，症状是 `rostopic list` 正常（只查 master）、`rostopic echo` 没数据（点对点连不上）。两种解法任选其一，**每台机都要设**：

- 直接 `export ROS_IP=本机IP`（推荐，绕过解析）；
- 或在所有机器 `/etc/hosts` 互相登记 `IP hostname`，再用 `ROS_HOSTNAME`。

单机部署保持 `localhost` 即可，见 [ros_env.sh](https://github.com/Romindly-Dev/romindly_robot_bringup/blob/main/robot_bringup/scripts/ros_env.sh) 中的注释。

部署完逐条跑，每条对应前面某章学过的能力：

| --- | --- | --- | --- |
| 1 | `rosversion -d` | `noetic` | 00 |
| 2 | `ls -l /dev/rplidar /dev/base_serial` | 软链存在 | 45 |
| 3 | `roslaunch robot_bringup robot.launch` | 无红字 ERROR | 45 |

## 常见问题

- **`apt update` 报 EXPKEYSIG**：见第二步，重装 ros.key 覆盖 `/usr/share/keyrings/ros-archive-keyring.gpg`。
- **`rostopic list` 有、`echo` 无数据**：hostname 解析问题，检查两端 `ROS_IP`/`/etc/hosts`。
- **拷贝 install 空间后节点缺 `.so`**：目标机少装了 apt 依赖，用 `ldd` 查缺哪个库，或在目标机跑一遍 `rosdep install`。
- **TF 报 extrapolation / lookup 时间超差**：先查 `chronyc sources`，多机时间没同步。
- **机器过夜后失联**：自动休眠没关干净，回第一步检查 `sleep.target` 是否 masked。
