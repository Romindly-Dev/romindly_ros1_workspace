# 02 键盘遥控与话题观察

> English version: [02_teleop_and_topics.md](../en/15_simulation/02_teleop_and_topics.md)

## 目标

- 用 `turtlebot3_teleop_key` 键盘遥控仿真小车
- 用 [10 章](../10_ROS1基础/02_话题通信.md)学过的 `rostopic` 系列工具摸清仿真机器人的四个核心话题：`/scan` `/odom` `/cmd_vel` `/imu`
- 读懂 `sensor_msgs/LaserScan` 和 `nav_msgs/Odometry` 两种消息的关键字段
- 用 `rqt_graph` 和 RViz 建立"数据流"的整体图像

## 原理简介

仿真小车的数据流是一条经典的移动机器人闭环：

```mermaid
graph LR
    teleop["teleop 节点<br>（键盘）"] -- "/cmd_vel<br>(Twist)" --> gazebo["Gazebo<br>差速驱动插件"]
    gazebo -- "/odom (Odometry)" --> algo["上层算法<br>（建图/导航）"]
    gazebo -- "/scan (LaserScan)" --> algo
    gazebo -- "/imu (Imu)" --> algo
```

- **`/cmd_vel`**（`geometry_msgs/Twist`）：唯一的控制入口。任何节点——键盘遥控、导航规划器、你自己写的脚本——只要往这个话题发速度指令，小车就动。差速小车只用两个字段：`linear.x`（前进 m/s）和 `angular.z`（转向 rad/s）。
- **`/odom`**（`nav_msgs/Odometry`）：里程计，Gazebo 插件根据轮子转动积分出的位姿+速度估计。特性与实机一致：短期平滑、长期漂移。
- **`/scan`**（`sensor_msgs/LaserScan`）：360° 激光雷达数据，是 20 章所有建图算法的输入。
- **`/imu`**（`sensor_msgs/Imu`）：角速度、线加速度和姿态，30 章 EKF 融合会用到。

这一篇不写任何代码，全部用现成工具——目的是让你养成"接手任何 ROS 系统先摸话题"的职业习惯。

## 分步操作

以下命令均需先启动仿真（终端 1）：

```bash
roslaunch turtlebot3_gazebo turtlebot3_world.launch
```

### 第 1 步：键盘遥控

终端 2：

```bash
roslaunch turtlebot3_teleop turtlebot3_teleop_key.launch
```

预期输出：

```
Control Your TurtleBot3!
---------------------------
Moving around:
        w
   a    s    d
        x

w/x : increase/decrease linear velocity (Burger : ~ 0.22)
a/d : increase/decrease angular velocity (Burger : ~ 2.84)
space key, s : force stop
```

**保持这个终端处于焦点**（点一下它）再按键：`w` 加速前进、`x` 减速/后退、`a`/`d` 左右转、`s` 或空格急停。注意它是"增减速"逻辑而非"按住才动"——按一下 `w` 小车会一直以该速度走，撒手不会停，要停按 `s`。开着遥控让小车在场地里转两圈，观察激光扫到圆柱时 Gazebo 里的蓝色射线变化（若未显示射线，无碍，RViz 里看更清楚）。

### 第 2 步：话题清单与频率

终端 3：

```bash
rostopic list
rostopic hz /scan /odom /imu
```

预期（频率有 ±10% 波动属正常，与 Real Time Factor 有关）：

```
        topic       rate   ...
       /scan        5.0
       /odom        30.0
       /imu         ~200
```

`Ctrl+C` 停止。再看 `/cmd_vel`：`rostopic hz /cmd_vel` 会显示 teleop 的发布频率——**只有你按键改变速度时才有新消息**，不按键时它可能长时间不发布（差速插件会维持上一条指令的速度），这解释了第 1 步"撒手不停"的现象。

### 第 3 步：读懂 LaserScan

```bash
rostopic echo -n 1 /scan
```

预期输出（ranges 数组很长，截取要点）：

```yaml
header:
  frame_id: "base_scan"
angle_min: 0.0
angle_max: 6.28318977355957
angle_increment: 0.01749303564429283
range_min: 0.11999999731779099
range_max: 3.5
ranges: [1.63, 1.62, 1.64, ..., inf, inf, ..., 0.58, ...]
```

字段解读：

- `angle_min`/`angle_max`：扫描起止角（弧度）。0 到 2π 表示整整一圈；0 弧度对应机器人**正前方**，逆时针增大。
- `angle_increment`：相邻两束激光的角度间隔，2π/360 ≈ 0.01745——即每 1° 一个点，一圈 360 个距离值。
- `ranges`：核心数据，360 个距离值（米），下标 i 的角度 = `angle_min + i × angle_increment`。`ranges[0]` 就是正前方障碍距离，`ranges[90]` 是正左方。
- `inf`：该方向在 `range_max`（3.5 m）内没打到东西；小于 `range_min`（0.12 m）的读数同样无效。
- `header.frame_id: base_scan`：数据是在雷达坐标系下表述的——要换算到别的坐标系就靠 TF，正是下一篇的主题。

验证理解：把小车遥控到离某根圆柱正前方约 0.5 m 处停下，再 `rostopic echo -n 1 /scan | grep -A1 ranges` 看 `ranges` 开头几个值是否 ≈ 0.5。

### 第 4 步：读懂 Odometry

```bash
rostopic echo -n 1 /odom
```

关键字段：

```yaml
header:
  frame_id: "odom"
child_frame_id: "base_footprint"
pose:
  pose:
    position: {x: 0.32, y: -0.11, z: -0.001}
    orientation: {x: ..., y: ..., z: 0.256, w: 0.966}
twist:
  twist:
    linear: {x: 0.05, ...}
    angular: {z: 0.0, ...}
```

- `pose`：`base_footprint` 在 `odom` 系下的位姿；姿态是四元数（回忆 [06 TF2 篇](../10_ROS1基础/06_TF2坐标变换.md)），平面机器人只有绕 z 的 yaw 分量。
- `twist`：当前速度，在 `child_frame_id`（机器人自身）系下表述——`linear.x` 就是前进速度。
- 遥控小车走一段再 echo，`position` 会持续变化；把小车推着（遥控）绕场一圈回到原地，`position` 不会精确归零——这就是里程计累积漂移，30 章定位要解决的正是它。

### 第 5 步：rqt_graph 看节点图

```bash
rqt_graph
```

把左上角下拉框设为 `Nodes/Topics (all)`。预期看到：`/turtlebot3_teleop_keyboard` 经 `/cmd_vel` 指向 `/gazebo`；`/gazebo` 发出 `/scan` `/odom` `/imu` 等。注意**整个仿真机器人在图上就是 `/gazebo` 一个节点**——所有传感器和底盘都是它内部的插件，这是仿真与实机（每个驱动一个节点）在节点图上的最大差别。

### 第 6 步：RViz 可视化

```bash
rosrun rviz rviz
```

手动配置一遍（比直接用现成 launch 更能练手）：

1. 左侧 `Global Options → Fixed Frame` 改为 `odom`。
2. `Add → RobotModel`：出现小车模型（读取的是 URDF，见 [07 篇](../10_ROS1基础/07_URDF机器人建模.md)）。
3. `Add → By topic → /scan → LaserScan`：红色点阵勾勒出六边形围栏和圆柱轮廓。看不清可把该显示项的 `Size (m)` 调到 0.03。
4. `Add → TF`：显示各坐标系箭头（下一篇细讲每一段）。

遥控小车移动，确认：模型在 RViz 中同步运动、激光点始终"贴"在障碍物上。这套显示配置 20 章建图还要用，可 `File → Save Config As` 存到 `~/ws_romindly/tb3_basic.rviz`。

## 动手练习

**让小车画圆**：关掉 teleop（避免指令打架），用 `rostopic pub` 直接发速度：

```bash
rostopic pub -r 10 /cmd_vel geometry_msgs/Twist \
  '{linear: {x: 0.1, y: 0, z: 0}, angular: {x: 0, y: 0, z: 0.5}}'
```

小车应以约 0.2 m 半径逆时针画圆（半径 = 线速度/角速度 = 0.1/0.5）。思考并验证：

1. 改哪个数能让圆变大一倍？（答案之一：`linear.x` 改 0.2）
2. `Ctrl+C` 停掉 pub 后小车为什么还在转？怎么让它停？（提示：发一条全零 Twist，`-1` 单次发布即可）
3. 在画圆的同时 `rostopic echo /odom` 观察 `position`，x/y 是否呈周期变化。

## 常见问题

**Q1：teleop 终端按键没反应。**
键盘事件只送给当前焦点窗口——先用鼠标点一下 teleop 终端。另外确认它没有报错退出（`TURTLEBOT3_MODEL` 未设置时 teleop 也会退出）。

**Q2：`rostopic hz /scan` 显示约 5 Hz，是不是太低了？**
不低，这是刻意仿真了 burger 实机 LDS-01 雷达的真实频率（约 5 转/秒）。建图算法就是按这个量级设计的。

**Q3：小车失控乱跑/原地打转。**
多半是 teleop 和 `rostopic pub` 同时在发 `/cmd_vel`，两路指令交替生效。任何时刻只保留一个 `/cmd_vel` 发布者；查一下现在谁在发：`rostopic info /cmd_vel` 看 Publishers 列表。

**Q4：RViz 里 RobotModel 一片白、报 `No transform from ...`。**
Fixed Frame 没设对（还留在默认的 `map`——现在还没有任何节点发布 map 系）。改成 `odom` 即可。这类 TF 报错的系统排查方法见下一篇。
