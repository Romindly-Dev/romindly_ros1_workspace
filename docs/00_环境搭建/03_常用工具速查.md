# 常用工具速查

## 目标

汇总 ROS1 日常调试最常用的命令行与图形工具，一行说明 + 示例，供随时查阅。建议先通读一遍，之后当手册用。

## 背景简述

ROS1 的调试围绕三类对象：节点（node）、话题（topic）、服务（service），外加参数（param）和消息/服务类型定义（msg/srv）。每类对象都有对应的 `ros*` 命令行工具；图形侧则以 rqt 系列和 RViz 为主。以下命令均需先 source 环境并保证 roscore（或某个 launch）在运行。

## 命令行工具

### rostopic — 话题

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `rostopic list` | 列出当前所有话题 | `rostopic list` |
| `rostopic echo` | 打印话题内容 | `rostopic echo /odom` |
| `rostopic hz` | 统计话题发布频率 | `rostopic hz /scan` |
| `rostopic info` | 查看话题类型及发布/订阅者 | `rostopic info /cmd_vel` |
| `rostopic type` | 只看消息类型 | `rostopic type /cmd_vel` |
| `rostopic pub` | 手动发布一条消息 | `rostopic pub -r 10 /cmd_vel geometry_msgs/Twist '{linear: {x: 0.2}}'` |
| `rostopic bw` | 统计话题带宽占用 | `rostopic bw /camera/image_raw` |

### rosnode — 节点

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `rosnode list` | 列出所有运行中节点 | `rosnode list` |
| `rosnode info` | 查看节点的话题/服务连接情况 | `rosnode info /move_base` |
| `rosnode ping` | 测试节点是否存活 | `rosnode ping /amcl` |
| `rosnode kill` | 杀掉指定节点 | `rosnode kill /rviz` |
| `rosnode cleanup` | 清理已死但未注销的节点 | `rosnode cleanup` |

### rosservice — 服务

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `rosservice list` | 列出所有服务 | `rosservice list` |
| `rosservice info` | 查看服务类型与提供节点 | `rosservice info /global_localization` |
| `rosservice type` | 只看服务类型 | `rosservice type /clear` |
| `rosservice call` | 调用服务 | `rosservice call /global_localization "{}"` |
| `rosservice args` | 查看服务请求参数格式 | `rosservice args /spawn` |

### rosparam — 参数

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `rosparam list` | 列出参数服务器全部参数 | `rosparam list` |
| `rosparam get` | 读取参数值 | `rosparam get /move_base/base_local_planner` |
| `rosparam set` | 设置参数值 | `rosparam set /amcl/min_particles 500` |
| `rosparam dump` | 导出参数到 YAML | `rosparam dump params.yaml /move_base` |
| `rosparam load` | 从 YAML 加载参数 | `rosparam load params.yaml /move_base` |
| `rosparam delete` | 删除参数 | `rosparam delete /foo` |

### rosmsg / rossrv — 类型定义

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `rosmsg show` | 查看消息字段定义 | `rosmsg show sensor_msgs/LaserScan` |
| `rosmsg list` | 列出所有消息类型 | `rosmsg list \| grep nav_msgs` |
| `rosmsg package` | 列出某包定义的消息 | `rosmsg package geometry_msgs` |
| `rossrv show` | 查看服务定义（`---` 上请求下响应） | `rossrv show nav_msgs/GetMap` |
| `rossrv list` | 列出所有服务类型 | `rossrv list \| grep std_srvs` |

## 图形与诊断工具

| 工具 | 说明 | 启动命令 |
| --- | --- | --- |
| rqt_graph | 可视化节点-话题连接图，排查"谁没连上谁"的首选 | `rqt_graph` |
| rqt_console | 集中查看各节点日志，可按级别/节点过滤 | `rqt_console` |
| rviz | 3D 可视化：TF、点云、地图、路径、模型等 | `rviz` |
| tf2_tools | 生成当前 TF 树 PDF（frames.pdf），排查坐标系断链 | `rosrun tf2_tools view_frames.py`，然后 `evince frames.pdf` |
| roswtf | 一键体检：检查环境、图连接、TF 等常见问题 | `roswtf` |

> 提示：`rosrun tf2_tools view_frames.py` 在 Noetic 中带 `.py` 后缀；老教程写 `view_frames` 的是 Melodic 及更早版本。

## catkin_make 与 catkin build

| | catkin_make | catkin build |
| --- | --- | --- |
| 来源 | ROS 自带 | catkin_tools 包，需另装 |
| 编译方式 | 全工作空间一个 CMake 工程 | 每个包独立编译、隔离环境 |
| 单包编译 | `catkin_make --only-pkg-with-deps <pkg>`（繁琐且有状态残留） | `catkin build <pkg>`（原生支持） |
| 出错定位 | 混在一起，不易读 | 按包分组输出，清晰 |
| 适合场景 | 小工作空间、跟官方教程 | 包多的实际项目（推荐） |

安装 catkin build：

```bash
sudo apt install -y python3-catkin-tools
```

常用命令：

```bash
cd ~/ws_romindly
catkin build          # 编译全部
catkin build urdf_demo  # 只编译指定包及其依赖
catkin clean          # 清理 build/devel/logs
```

**注意**：同一工作空间不能混用两种工具。若之前用过 `catkin_make`，切换前先删除 `build/` 和 `devel/`（或执行 `catkin clean`）。本套件文档默认使用 `catkin_make`，两者选一坚持即可。

## 常见问题排查

- `rostopic echo` 无输出但 `rostopic info` 显示有发布者：多为消息类型不匹配或 TF/仿真时间问题，先 `rostopic hz` 确认确实在发。
- 多个终端命令都报 `Unable to communicate with master`：roscore 未运行，或 `ROS_MASTER_URI` 指向了不可达地址（多机场景常见）。
- rqt 系列窗口打不开（SSH）：需要图形环境，用 `ssh -X` 或在本机桌面运行。
- `rosmsg show` 找不到自定义消息：该消息所在包未编译或未 source `devel/setup.bash`。
